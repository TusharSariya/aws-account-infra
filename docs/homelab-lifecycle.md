Helm owns retained volumes, the approved JSON/YAML Pod template, controller code/configuration, Argo and reviewed templates. The lifecycle controller alone owns `ai-runtime`, its desired state, command revision, active tickets and replica count. A Helm change while AI is running waits for an explicit shutdown before adopting the new Pod template. CI never starts AI to check its health.

The four-container Pod requests and initially limits 31.25 CPU and 77 GiB RAM in total. It stays Pending as one unit when those resources do not fit. Pi-hole and platform components have independent requests. Each Argo executor reserves 100m CPU and 256 MiB RAM, with 500m CPU and 512 MiB RAM limits; its initial 64 MiB limit was insufficient for live initialization. Executor ephemeral storage reserves 192 MiB and limits 256 MiB. The reviewed templates bound Argo's staged-binary and temporary volumes to 192 MiB and 16 MiB; these are Kubernetes eviction thresholds, not filesystem hard quotas. No VM resources or disks were changed. Models, workspace and vector data use retained 300/20/10 GiB quota-limited directories on the existing shared XFS filesystem. Limits permit overcommit and do not reserve physical space.

The model gateway is compiled into the pinned Ollama server. Its authenticated port is 11434; native inference uses sockets in the Ollama container's private `/tmp` rather than a bypassable same-Pod TCP port. Only workspace inference can continue an already admitted work tree while draining. Downloads, uploads and model mutations always require fresh admission. Reviewed CI image records bind immutable digests to source inputs and successful image workflows through immutable build-produced receipts. CI verifies artifact ownership, source commit, input hash, image digest and archive checksum. A failed, cancelled, skipped, stale or expired build receipt blocks deployment. Receipt retention is 90 days; renew the verified build evidence before it expires.

## Credentials and private operations

`python3 scripts/issue-lifecycle-credentials.py NEW_PRIVATE_DIRECTORY` creates five independent 256-bit values. Keep `credentials.json` private and upload `github-secret.b64` to the protected `prod` secret `AI_LIFECYCLE_CREDENTIALS_B64` using stdin. The bundle never enters OpenTofu values, plans or state. The controller receives operator and per-source credentials; each application mounts only its required source/model keys. The direct model-user key is separate from the workspace continuation key.

The initial local issuance is in `~/.config/aws-account-infra/lifecycle/initial`. No offline credential backup is claimed. Securely retain a separate encrypted copy according to the existing credential recovery procedure. Stop AI before rotating source/model credentials, then update the protected bundle through the normal CI apply. Rotating only one side while writers run closes verification and can prevent graceful drain. An API credential alone cannot recover deleted application data.

With Tailscale connected, read status:

```sh
python3 scripts/ai-control.py status --credentials ~/.config/aws-account-infra/lifecycle/initial/credentials.json
```

Issue `start`, `stop` or `force-stop` with the revision returned by Status. The client prints a command UUID before sending. For an ambiguous network result, retry that same UUID and original revision with `--command-id`. Never automatically refresh the revision and replay a stale Start after another operator stopped AI.

Start requires completed migration and healthy, fresh capacity measurements. Starting/Pending is distinct from On. Stop closes admission and waits for verified active work; it has no automatic force deadline. Force Stop records interrupted tickets and requests the Pod's bounded 30-second termination grace, but reports Off only after termination is observed. Pressure never invokes Force Stop or deletes data.

A source heartbeat is accepted only after a fresh authenticated process-identity challenge to the running Pod. Container restart alone cannot resurrect old messages; observed termination retires interrupted work. Unknown activity blocks admission, graceful completion and idle shutdown. Controller recovery restarts the inactivity interval. The configured continuous verified idle interval requests Stop. Set `config.idleTimeoutSeconds` in `config/environments/kubernetes/homelab/lifecycle-values.yaml` and deploy the reviewed change. The chart defaults to 1800 seconds (30 minutes); this homelab selects 300 seconds (5 minutes). Only integers from 60 to 86400 are accepted. Status reports `idle_timeout_seconds`; a configuration rollout starts a fresh interval. Health requests, browser heartbeats, replay subscriptions and idle thread pools do not count as work; scheduled executions, agents, document processing, streams and subprocess descendants do.

Capacity is collected every 30 seconds. Missing, unhealthy or older-than-90-second samples close admission. At 80% usage the controller warns; 90% or unavailable telemetry also requests graceful drain. Five continuous healthy minutes below 80% clear the gate, but a drained runtime remains off until explicitly started. `StorageCapacityPressure` Warning events provide the alert; no external paging integration is claimed.

## Argo access and execution

The UI/API is `https://argo.tail2f646b.ts.net`, with client-token authentication and namespace-scoped permissions. With the existing private kubeconfig and checksum-verified kubectl, `python3 scripts/argo-client-token.py NEW_PRIVATE_TOKEN_FILE` issues a 30-minute token for `homelab-workflow-client`. Use that token in Argo's client-token login. It cannot read Secrets, create Pods directly or edit templates/schedules. Token expiry requires a new issuance; no durable broad Kubernetes token is needed.

Submit the reviewed `smoke` or `independent-smoke` WorkflowTemplate for ordinary work. The initially suspended `scheduled-smoke` CronWorkflow uses UTC, `Forbid` and the same `smoke` mutex as manual/API submissions. Independent template mutexes allow concurrent jobs when resources fit. The Kubernetes admission policy rejects inline templates, arbitrary service accounts, Pod overrides and unreviewed template references before execution. Ordinary job service accounts can only create/patch Argo task results and hold no lifecycle or host-storage credential.

The `ai-status`, `ai-start`, `ai-stop` and `ai-force-stop` templates call the lifecycle API. Supply a canonical `command-id` and current `revision` for a new command. These operation templates deliberately share no mutex: a pending Start must not prevent Stop. Their job service account receives only the lifecycle operator credential and ordinary Argo result-writing permission.

Argo cancellation cancels the workflow and its observer Pod. It does not reverse a lifecycle command already committed by the controller. To stop AI, issue the reviewed Stop operation explicitly. Workflow observation may time out after 24 hours while graceful drain remains pending; this never escalates to Force Stop. Modify schedules only through reviewed configuration or the explicit maintenance acceptance workflow, then restore the suspended setting.
